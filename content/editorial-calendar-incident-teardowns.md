# Incident Teardown Editorial Calendar

**Objective**: Establish repo.box as the authoritative voice on repository access control through technical analysis of real-world security incidents.

**Frequency**: 1 incident teardown post per month
**Target Audience**: DevOps engineers, security architects, CTOs

## Source Selection Criteria

### Primary Requirements

**Incident Characteristics:**
- Public investigation report or detailed post-incident analysis available
- Clear access control or permission management failure component
- Sufficient technical detail to create actionable insights
- Incident occurred within 18 months of publication date
- Impact scale suitable for corporate/enterprise audience

**Technical Focus Areas:**
- Repository and code access management failures
- Credential theft and privilege escalation
- Supply chain security incidents
- DevOps/CI-CD pipeline compromises
- Multi-tenant platform breaches
- Administrative tool compromises

### Quality Thresholds

**Required Information Depth:**
- Timeline of attack progression
- Technical details of access control failures
- Documented blast radius and impact assessment
- Official remediation steps and policy changes
- Public investigation findings or court documents

**Exclusions:**
- Incidents without sufficient public technical detail
- Attacks not related to access control or permission systems
- Confidential or client-privileged information
- Speculation-based analysis without hard evidence
- Inflammatory or sensationalized coverage

## Target Incident Categories

### High Priority
